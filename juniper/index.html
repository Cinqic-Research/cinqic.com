01 — Model control

Choose a model without becoming a systems administrator.

Juniper’s Models Market detects the device profile, explains which compact models fit, and manages verified downloads and storage.

01

Device-aware recommendations

Review a curated catalog of four instruction-tuned GGUF models below 1B parameters with source revision, license, size, and SHA-256 details.

02

Verified model lifecycle

Downloads are resumable and integrity-checked, with atomic installation, pause/resume, and removal.

03

Model-agnostic by design

No model family is required and no model is bundled in the installer. Compatible providers and runtimes remain visible choices.

04

Juniper-owned desktop runtime

The desktop bundle owns its loopback llama.cpp process, so ordinary local use does not require Ollama or an account.

02 — Assistant workspace

A useful assistant with the controls exposed.

The chat workspace supports streaming, Markdown, export, private chats, and mobile layouts. Assistant profiles keep personality, model choice, tool policy, memory policy, import, and export in one place.

Optional provider connections include Ollama, OpenAI-compatible servers, and llama.cpp-compatible servers for advanced users and existing setups.

Context

Deterministic composition

System prompt, assistant settings, memories, enabled tools, and recent conversation stay within a context budget.

Tools

Explicit permissions

Host-authored calculator, conversion, datetime, attachment, memory, search, and system-info contracts.

Storage

Local persistence

SQLite application state, scoped text attachments, diagnostics, and private-chat boundaries.

03 — Data boundaries

The app should tell you where your prompt goes.

Juniper labels routes as ON DEVICE, LOCAL NETWORK, REMOTE, or UNKNOWN, and never treats UNKNOWN as safe. Desktop provider credentials use the operating-system credential store and Android provider credentials use Android Keystore; secrets are not written to SQLite or exports.

Telemetry, analytics, crash reporting, and accounts are not part of this release. A tool the request did not enable is denied rather than executed.

04 — Interface

Conversation first.

Juniper 0.3.0-rc.33 keeps three destinations — Chats, Models, and Settings. Reasoning, tool activity, and model details stay one tap away instead of on screen, and the model pill shows whether a reply runs ON DEVICE, LOCAL NETWORK, or REMOTE.

Appearance is a set of validated settings: system, light, or dark; standard or high contrast; curated, neutral, or custom accent colors with readable text shades computed for you; bundled Inter, Atkinson Hyperlegible Next, and OpenDyslexic fonts; and density, conversation width, message style, text size, and motion. Nothing is downloaded and no custom code is loaded.

05 — Published release

0.3.0-rc.33 is available for evaluation.

This is the latest public Juniper release verified on GitHub, and it matches the current source version. It is a prerelease candidate, not a promoted 0.3.0 release.

0.3.0-rc.33 rebuilds the interface around the conversation: Chats, Models, and Settings are the only primary destinations, conversation actions move into an overflow menu, and a model picker labels where every model runs. It adds validated appearance settings, and fixes an Android layout that drew under the status bar and keyboard, a back gesture that left the app instead of closing menus and dialogs, and a startup crash on older Android System WebView builds.

06 — Known limitations

The boundaries are part of the release.

Android native local inference is available in Beta through an in-process llama.cpp bridge for managed, SHA-256-verified GGUF models on ARM64; a physical ARM64 run is still required before that runtime is promoted beyond Beta. Device Link and Juniper Network remain non-networked protocol and policy work, with pairing, discovery, peer connections, and remote control disabled. MCP client calls, iOS, and macOS are not included; the Windows MSI may also trigger an unsigned-app warning.
